# DL-003 — Microcontroller Selection

**Date:** 2026-08-17
**Status:** Accepted

---

## 1. Decision

The **ESP32** was selected as the main microcontroller for Project MO V1.

It will serve as the central processing and control unit, coordinating the project's inputs, outputs, audio system, and overall behavior.

---

## 2. Context

Project MO requires a capable microcontroller that can manage multiple peripherals and communication interfaces while remaining affordable, compact, and suitable for an embedded system.

The controller also needs sufficient processing capability and connectivity to support the planned V1 features while providing opportunities for future expansion.

---

## 3. Alternatives Considered

| Option           | Advantages                                                                                               | Disadvantages                                                     |
| ---------------- | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| **ESP32**        | Strong processing capability, many GPIO pins, built-in wireless connectivity, low cost, widely supported | Higher complexity than simpler microcontrollers                   |
| **Arduino Uno**  | Simple to program, widely documented, beginner-friendly                                                  | More limited processing power, memory, and connectivity           |
| **Raspberry Pi** | Much greater processing capability and software flexibility                                              | Higher cost, power consumption, and unnecessary complexity for V1 |

---

## 4. Rationale

The ESP32 was selected because it provides a strong balance between **processing capability, available interfaces, connectivity, cost, and future expandability**.

Its GPIO availability allows it to interface with the project's various peripherals, while its built-in wireless capabilities provide opportunities for future features without requiring an additional communication module.

The ESP32 also provides considerably more capability than required for the basic V1 functionality, creating room for future development without requiring an immediate change to the main controller.

---

## 5. Consequences

### Positive

* Provides sufficient processing capability for V1.
* Offers a large number of GPIO and communication interfaces.
* Includes built-in Wi-Fi and Bluetooth connectivity.
* Provides room for future hardware and software expansion.
* Keeps the main control system relatively compact and affordable.

### Trade-offs

* More complex than simpler microcontrollers such as the Arduino Uno.
* Some of its capabilities will not be fully utilized during V1.
