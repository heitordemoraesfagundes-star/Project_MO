# DL-008 — Documentation & Repository Structure

**Date:** 2026-08-15
**Status:** Accepted

---

## 1. Decision

Project MO will use a **structured GitHub repository with dedicated engineering documentation, development records, decision logs, source files, and project assets**.

Documentation will be separated according to its purpose rather than maintained as a single project document.

---

## 2. Context

As Project MO expanded beyond its initial concept, it became necessary to organize the increasing number of technical documents, design files, component information, development records, and project assets.

A structured repository was needed to make the project easier to navigate, maintain, and understand by someone who was not involved in its development.

---

## 3. Alternatives Considered

| Option                           | Advantages                                                                                | Disadvantages                                        |
| -------------------------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| **Structured repository**        | Organized; scalable; easier to navigate; clearly separates different types of information | Requires additional organization and maintenance     |
| **Single project document**      | Simple to maintain initially                                                              | Difficult to navigate and scale as the project grows |
| **Unstructured file repository** | Minimal setup                                                                             | Makes information difficult to locate and understand |

---

## 4. Rationale

A structured repository was selected because Project MO is intended to demonstrate not only the final product, but also the **engineering process used to develop it**.

Separating technical documentation, development history, engineering decisions, hardware, software, CAD, and other project assets makes the repository easier to maintain and provides a clear record of the project's development.

GitHub was selected as the primary platform because it provides version control, public accessibility, and a suitable environment for documenting an engineering project.

---

## 5. Consequences

### Positive

* Makes the project easier to navigate.
* Preserves the reasoning and development history behind MO.
* Allows documentation and project files to evolve independently.
* Provides a clear portfolio of the complete engineering process.
* Makes future collaboration and expansion easier.

### Trade-offs

* Requires consistent organization as the project grows.
* Documentation must be maintained alongside development.
