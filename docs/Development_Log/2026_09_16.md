## Work Completed

### Arduino IDE and ESP32 Platform Setup

Arduino IDE 2.3.10 was prepared for ESP32 development. The official **esp32 by Espressif Systems** board package, version 3.3.11, was installed through the Boards Manager.

The connected controller was visually identified as a **DOIT ESP32 DEVKIT V1** with the classic ESP32 module and 30-pin layout. The matching board profile was selected in Arduino IDE.

### USB Data Connection Verification

After the ESP32 support package and drivers were installed, Windows detected the board as **COM3 Serial Port (USB)**. This resolved the previous inconclusive cable test.

A basic serial-output sketch was compiled and uploaded successfully. Arduino IDE reported that the written data was verified and reset the controller through the RTS line. The Serial Monitor then displayed the expected repeating Project MO status message at 115200 baud.

The available USB-A to Micro-USB cable is therefore confirmed to support both power and data and can be retained as the V1 programming and bench-test cable.

### Command Prototype V0.1

The first firmware prototype was saved as **Project_MO_Command_Prototype**. It reads text commands from the Serial Monitor, normalizes the input with trimming and lowercase conversion, and routes the result through an `executeCommand()` function.

The initial command set included:

- `hello mo`
- `status`
- `sleep`
- `wake up`
- `who are you`

Tests confirmed the expected response for every recognized command and the correct fallback message for an unrecognized input.

### Greeting Alternatives

The greeting condition was expanded with logical OR operators so that the following phrases produce the same response:

- `hello mo`
- `hi mo`
- `hey mo`

All three alternatives compiled, uploaded and executed correctly.

### Active and Sleeping States

A Boolean `sleeping` state was added to the command prototype.

The verified sequence was:

1. `sleep` changed the internal state to sleeping.
2. Normal commands were rejected while MO was sleeping.
3. `wake up` restored the active state.
4. Greeting commands worked again after reactivation.

This created the first persistent runtime state in the Project MO firmware. The current state resets to active whenever the ESP32 restarts because no non-volatile storage has been implemented.

### Voice-Command Architecture

The V1 command flow was separated into two layers:

1. A future speech-recognition layer will convert microphone audio into text.
2. The existing `executeCommand()` function will interpret that text and trigger the correct action.

Serial Monitor input is being used as a temporary substitute for recognized speech. This allows the command logic to be developed and tested before the complete audio-input system is available.

### INMP441 Microphone Identification

The received circular microphone board was visually identified as an **INMP441 digital MEMS microphone module**. The labeled connections are:

- SCK
- WS
- L/R
- SD
- VDD
- GND

The module uses the I²S digital interface and must operate from 3.3 V. The L/R channel-selection pin must eventually be tied to either ground or 3.3 V rather than left floating.

Male header pins were included with the module but remain unsoldered. Their orientation will be selected only after the final mounting direction, acoustic opening and GPIO allocation are confirmed. A soldering iron still needs to be bought or borrowed before physical integration.

### MicroSD Allocation

The 32 GB microSD card was reserved for transferring the Nextion HMI interface through the display's built-in microSD slot.

No separate ESP32 microSD reader is planned for V1. This avoids adding another module and consuming additional GPIO pins. Small initial sound assets may instead use ESP32 internal storage if required.

### Speech-Recognition Comparison Phrase Set

A fixed ten-phrase test set was selected for the planned comparison of candidate speech-recognition APIs:

1. `Hello MO`
2. `Hi MO`
3. `Hey MO`
4. `MO, go to sleep`
5. `Wake up, MO`
6. `MO, what is your status?`
7. `MO, show a happy face`
8. `MO, play a sound`
9. `MO, set a timer for fifteen minutes`
10. `This sentence should not activate MO`

Each phrase will be tested under three conditions:

- Quiet room at approximately 30 cm.
- Quiet room at approximately 1 m.
- Moderate background noise at approximately 30 cm.

This produces 30 recordings per candidate model. The planned comparison criteria are transcription accuracy, correct command selection, response time, false activation, internet requirement and estimated cost.

## Engineering Decisions

- Use Arduino IDE with the official Espressif ESP32 package for the V1 firmware prototype.
- Use the **DOIT ESP32 DEVKIT V1** board profile and COM3 for the received controller.
- Retain the existing Micro-USB cable as the programming and bench-test cable.
- Keep command interpretation separate from speech recognition.
- Use Serial Monitor text as the temporary command input during early firmware development.
- Support multiple natural greeting phrases through one shared response block.
- Implement active and sleeping software states before adding display and audio actions.
- Use the INMP441 at 3.3 V through I²S.
- Do not solder the microphone headers until mounting orientation and GPIO allocation are confirmed.
- Reserve the microSD card for Nextion interface transfer during V1.
- Use one fixed phrase set and identical test conditions for every candidate speech-recognition model.

## Current Risks and Open Questions

- The INMP441 has not yet received an electrical or audio-input test.
- A soldering iron must still be bought or borrowed.
- The final microphone header orientation and acoustic mounting direction remain open.
- The definitive GPIO map must account for the INMP441, MAX98357A, Nextion UART and seven physical buttons.
- The MAX98357A and Nextion connector layouts still require physical confirmation.
- Candidate speech-recognition APIs have not yet been selected.
- Speech-recognition performance with the user's accent, distance and background noise is unknown.
- The sleeping state is not retained after an ESP32 restart.
